# 埋め込み計算と TabPFN 専用の隔離環境（.venv-embed）の依存。
# 主環境の requirements.txt とは別物。
#
# なぜ主環境と分けるのか（2026/9/1 に理由が入れ替わった）:
#   もともとは依存の衝突を避けるためだった。Intel Mac に入る torch は 2.2.2 が上限で、
#   それは numpy 1.x でビルドされていたので、主環境の numpy 2.x と共存できなかった。
#   計算ノード（Ubuntu / x86_64）に移ってこの制約は消え、torch は主環境にも入る。
#
#   それでも分けたままにしているのは、**unfold が torch 無しで動くことの番人**だから。
#   既定エンコーダは文字 TF-IDF で、torch を必須にしない設計にしてある
#   （unfold/encoders.py、PRD §GPU 非前提）。主環境に torch を入れてしまうと、
#   ライブラリのどこかが誤って torch に依存してもテストが通ってしまい気づけない。
#
# 対象は計算ノード（Linux / x86_64）。Intel Mac ではこの組み合わせは解決しない
# （torch が 2.2.2 までしか入らないため）。移行前の Mac 向けピンは git 履歴にある。
# torch は CPU 版インデックスから入れる（ノードに GPU は無く、既定の PyPI から入れると
# CUDA の wheel が19個ぶら下がってくる）。scripts/setup_embed_env.sh を使うこと。

torch==2.13.0
numpy
pandas
pyarrow

# 表形式データの基盤モデル（PRD の P0.5 / R6 のベースライン）。
#
# 2.2.1 に留め置いている。理由が 9/1 に入れ替わっているので注意すること。
#   旧: Intel Mac の torch が 2.2.2 上限で、torch>=2.5 を要求する 8.x が入らなかった
#   新: その制約はノードで消えたが、**7.1.0 以降はモデル重みの取得に
#       Prior Labs のライセンス承諾（TABPFN_TOKEN）が要る**。測定のためだけに
#       外部サービスへ登録するのは割に合わないと判断した
#
# 副次的な利点として、2.2.1 は PRD が R6 として引用している Nature 2025 の版
# そのものであり、8/29 の測定と直接比較できる。
# 関門なしで入る最も新しい版は 7.0.0（→ docs/2026-09-01-embed-env-rebuild.md）。
tabpfn==2.2.1

# torch は 2.13 のままで動く（2.2.2 上限だったのは Mac の事情なので引きずらない）。
transformers==4.57.6
