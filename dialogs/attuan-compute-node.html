attuan の計算機ノード

手元の PC の代わりに使える、16 コアの計算機を AWS 上に用意しました。 使うときに自分で電源を入れ、終わったら自分で切ります。 このページはその手順書です。上から順にやれば動きます。

16 vCPU 64 GiB RAM 200 GB SSD Ubuntu 24.04 m7i.4xlarge us-east-1

まず、これだけは覚えてください

このマシンは「使っている時間」に対してお金がかかります。電源の入切がそのまま費用です。

CPU 使用率が 5% 未満の状態が 1 時間続くと、自動でシャットダウンされます（消し忘れ対策）。 ただし 1 コアしか使わない長い計算は、16 コア全体では 5% を下回って止められることがあります。 長時間ジョブを流すときは事前に katsuyaito に声をかけてください。しきい値を上げます。

これはやらないでください

terminate（削除）はマシンとディスクの中身を丸ごと消します。取り消せません。 止めたいときは必ず stop（停止）を使ってください。

セットアップ

1 から 4 は最初の 1 回だけ。5 と 6 が毎日の作業です。チェックは自動で保存されます。

  1. 01
    AWS にサインインする

    ユーザー名・初回パスワード・アクセスキーは、このページとは別の経路（1Password か Slack の DM）で渡します。 このページには載せていません。

    サインイン URL
    https://697441478678.signin.aws.amazon.com/console
    アカウント ID
    697441478678
    IAM ユーザー名
    attuan
    リージョン
    us-east-1（バージニア北部）

    初回ログイン時にパスワードの変更を求められます。新しいパスワードはパスワードマネージャーに保存してください。 画面右上のリージョンが N. Virginia になっていることも確認します。ここが違うとマシンが一覧に出てきません。

  2. 02
    手元の PC に AWS CLI を入れる

    macOS / Linux なら次の通り。Windows なら WSL の中で同じことをします。

    # AWS CLI v2
curl -fsSL "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip
unzip -q awscliv2.zip && sudo ./aws/install

# Session Manager プラグイン（サーバーに入るのに必要）
curl -fsSL "https://s3.amazonaws.com/session-manager-downloads/plugin/latest/ubuntu_64bit/session-manager-plugin.deb" -o smp.deb
sudo dpkg -i smp.deb

    入ったか確認します。両方バージョンが出れば成功です。

    aws --version
session-manager-plugin --version
  3. 03
    アクセスキーを設定する

    渡されたアクセスキーを登録します。リージョンは必ず us-east-1 にしてください。

    aws configure
#   AWS Access Key ID     : 渡されたもの
#   AWS Secret Access Key : 渡されたもの
#   Default region name   : us-east-1
#   Default output format : json

    自分として認識されているか確認します。末尾が user/attuan なら成功です。

    aws sts get-caller-identity
    キーの扱い

    アクセスキーはあなた自身です。GitHub・Slack の公開チャンネル・スクリーンショットに絶対に載せないでください。 うっかり出してしまったら、隠さずすぐ katsuyaito に連絡を。無効化して作り直すだけで済みます。

  4. 04
    SSH 鍵と接続設定を置く

    渡された attuan-key.pem を ~/.ssh/ に置き、権限を絞ります。 

    mv ~/Downloads/attuan-key.pem ~/.ssh/attuan-key.pem
chmod 400 ~/.ssh/attuan-key.pem

    次に ~/.ssh/config に以下を追記します。 このサーバーはインターネットにポートを一切開けていません。AWS の Session Manager を通り道にして入るので、 この ProxyCommand の行が必要です。 

    Host attuan
    HostName i-01b5d31ffbff67135
    User ubuntu
    IdentityFile ~/.ssh/attuan-key.pem
    ProxyCommand sh -c "aws ssm start-session --target %h --document-name AWS-StartSSHSession --parameters portNumber=%p --region us-east-1"

    これで ssh attuan だけで入れるようになります。

  5. 05
    起動して、つなぐ

    作業を始めるときの手順です。起動には 30 秒ほどかかります。

    # 電源を入れる
aws ec2 start-instances --instance-ids i-01b5d31ffbff67135

# 起動しきるまで待つ
aws ec2 wait instance-running --instance-ids i-01b5d31ffbff67135

# 入る
ssh attuan

    ブラウザからでも同じことができます。AWS コンソール → EC2 → インスタンス → indx-internal-dev-us-east-1-attuan-compute を選んで 「インスタンスの状態」→「インスタンスを開始」。

    VSCode から使う

    拡張機能 Remote - SSH を入れて、接続先に attuan を選ぶだけです。 ステップ 4 の ~/.ssh/config をそのまま読んでくれます。 ただし VSCode で開く前にサーバーを起動しておくこと。止まっているとタイムアウトします。

    作業場所

    /work を共有の作業ディレクトリとして用意してあります。 Python は 3.12 が入っています。プロジェクトごとに仮想環境を切ってください。 

    cd /work
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
    長い計算をするとき

    tmux を使ってください。SSH が切れても計算は生き残ります。 tmux で開始、Ctrl+B → D で離脱、 tmux attach で戻る。これを覚えるだけで作業が一気に楽になります。

  6. 06
    終わったら止める

    ここが一番大事です。作業を切り上げるときは必ず止めてください。 ディスクの中身は残るので、次に起動すれば続きから作業できます。 

    aws ec2 stop-instances --instance-ids i-01b5d31ffbff67135

    止まったかどうかは、いつでもこれで確認できます。

    aws ec2 describe-instances --instance-ids i-01b5d31ffbff67135 \
  --query 'Reservations[0].Instances[0].State.Name' --output text

    stopped と出れば止まっています。 stopping は停止処理の途中、running はまだ課金されています。

できること / できないこと

このアカウントは Owner タグが attuan の資源だけ を触れるように制限されています。 他の人のサーバーは、見えても操作できません。壊す心配をせずに触ってください。

操作可否補足
自分のマシンの起動・停止・再起動できる毎日使う操作
Session Manager / SSH で入るできるポート開放なしで入れる
自分のパスワード・アクセスキーの管理できるMFA の設定も自分でできる
EC2 の一覧を見るできる他人のマシンも一覧には出る
自分のマシンの削除（terminate）できるディスクごと消える。基本使わない
他人のマシンの操作できないタグで弾かれる
新しいサーバーに権限ロールを付けて起動できない必要なら katsuyaito が用意する
IAM ユーザーや権限の作成・変更できない—
S3・RDS などその他のサービスできない必要になったら相談してください

うまくいかないとき

ほとんどはこの 5 つのどれかです。10 分試してだめなら、遠慮なく聞いてください。

ssh がつながらない / タイムアウトする

まずサーバーが動いているか確認します。stopped なら起動してください。 起動直後は Session Manager の準備に 1 分ほどかかることがあります。

UnauthorizedOperation と言われる

だいたいリージョン違いです。aws configure get region が us-east-1 になっているか確認してください。 コマンドに --region us-east-1 を付けても直ります。

気づいたら勝手に止まっていた

自動停止が働いています。CPU がほぼ遊んでいる状態が 1 時間続いた合図です。 計算中に止められたなら、しきい値の調整が必要なので教えてください。

ディスクが足りない

df -h / で残量を確認できます。200 GB を超えそうなら拡張できるので相談してください。 一時ファイルの置きっぱなしが原因のことも多いです。

パッケージが入れられない

サーバーの中では sudo が使えます。 sudo apt install … で自由に入れて構いません。壊しても作り直せます。

手元に控えておく値

パスワードとアクセスキーはここには含めません。別経路で渡したものを使ってください。
