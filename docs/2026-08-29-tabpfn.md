# TabPFN は LightGBM に並んだが、超えなかった（P0.5 の片方が埋まった）

**日付**: 2026-08-29
**結論**: シエンタ 5,507行で **TabPFN の MAE は 12.95 万円**。
同じ列を使った LightGBM の **12.88 万円**と**実質同着**（差 0.07、fold 間の振れ ±0.19〜0.33 の範囲内）。
全体最良の 12.21（＋装備テキストの文字TF-IDF）には **0.74 届かなかった**。

**PRD §9 の「TabPFN に負ける可能性」というリスクは、少なくともシエンタでは顕在化しなかった。**

---

## 1. なぜ測ったか

PRD の P0.5。TabPFN は **LLM を一切使わない側の到達点**であり、
これを超えられないと「LLM で精度を上げた」という主張が成立しない（R6）。
機能A を実装する前に線を引いておく必要があった。

## 2. TabPFN とは何か

**Tab**ular **P**rior-data **F**itted **N**etwork。表形式データ用の基盤モデル。

LightGBM は「データを見せて訓練する」道具で、データが変われば訓練し直す。
TabPFN は**その場での訓練をしない**。人工的に生成した何百万個もの架空の表データで
**事前学習を済ませた Transformer** で、使うときは訓練データを**入力として丸ごと渡し**、
1回の推論で答えを出す。LLM に例文をいくつか見せてから質問する few-shot と同じ仕組みで、
**in-context learning（文脈内学習）** と呼ばれる。

Transformer を使ってはいるが、**TabPFN は LLM ではない。**
学習したのは言葉ではなく表データの構造である。本プロジェクトの主張に関わるので区別が要る。

## 3. 測定条件

| 項目 | 内容 |
|---|---|
| データ | シエンタ 5,507行（1 fold あたり 訓練4,405 / 予測1,102） |
| 列 | LightGBM の「B 構造化列フル」と**同一**（数値4・真偽3・カテゴリ4の計11列） |
| プロトコル | KFold(5, shuffle, seed=42)。既存の全実験と共通 |
| 実装 | tabpfn 2.2.1 / CPU / `.venv-embed` |

カテゴリ列は train に出た水準だけで整数に振り直し、test にしか無い水準は NaN にした
（LightGBM 側の `as_category` と同じ扱い）。どの列がカテゴリかは
`categorical_features_indices` で明示している。

## 4. 結果

| 手法 | MAE（万円） | 振れ幅 | RMSE | R² |
|---|---:|---:|---:|---:|
| C2 B+装備テキスト(文字TF-IDF)（全体最良） | **12.21** | ±0.42 | 16.49 | 0.953 |
| D3 構造化列フル+タイトル埋め込み | 12.38 | ±0.40 | 16.60 | 0.952 |
| **B LightGBM・構造化列フル**（同じ列＝直接の相手） | **12.88** | ±0.19 | 17.22 | 0.949 |
| **F TabPFN・構造化列フル (n_est=8)** | **12.95** | ±0.33 | 17.32 | 0.948 |
| F TabPFN・構造化列フル (n_est=1) | 13.06 | ±0.32 | 17.51 | 0.947 |

**同じ列で比べると LightGBM 12.88 対 TabPFN 12.95。差は 0.07 万円（700円）で、
fold 間の振れ（±0.19〜0.33）より小さい。統計的には区別がつかない。**

一方、**テキストを足した C2（12.21）には 0.74 差をつけられている。**
これは振れ幅を超えるので実質的な差と見てよい。

### 示唆

- **表の列だけを与える限り、TabPFN も LightGBM も同じところで頭打ちになる。**
  モデルを替えても伸びず、**伸びしろは非構造テキストの側にある。**
  これは本プロジェクトが機能A（特徴量生成）に賭けている前提を支持する。
- 先行事例 R1（車両28万件でも木系アンサンブルが最強）と整合する。
- ただし**「TabPFN に楽勝した」わけではない**。同着なので、
  「LightGBM を使う理由」は精度ではなく速度と運用性の側にある（下記）。

## 5. 費用の比較

| | 5-fold の所要 |
|---|---:|
| LightGBM（構造化列フル） | 数秒 |
| TabPFN n_estimators=1 | **148秒** |
| TabPFN n_estimators=8（既定） | **1,015秒（17分）** |

**同じ精度に約200〜400倍の計算時間を払っている。**
`n_estimators`（内部で何通りの前処理を試して平均するか）を既定の 8 から 1 に落とすと
所要は7分の1になり、MAE の悪化は 0.11 に留まる。**探索段階では 1 で十分。**

## 6. 環境まわりの知見

### 最新版は入らないが、問題にならない

このマシン（Intel Mac）に入る torch は **2.2.2 が上限**（x86_64 向けビルドが打ち切られている）。
TabPFN 最新版 8.5.0 は `torch>=2.5` を要求するので入らない。
一方 **2.2.1 は `torch>=2.1,<3`** なので既存の `.venv-embed` にそのまま乗る。
新しい venv は不要だった。

**そして 2.x 系は PRD が R6 として引用している Nature 2025 の版そのもの**なので、
比較対象としてはむしろこちらが正しい。最新版が入らないことは実質的な不利益にならない。
（TabPFN 8.x は Apple Silicon 専用の `mlx` にも依存しており、そこでも Intel Mac は対象外）

> **【9/1 追記】** 計算ノードへの移行で torch の上限は消えたが、**2.2.1 のまま
> 進めると決めた**。7.1.0 以降はモデル重みの取得に Prior Labs のライセンス承諾
> （`TABPFN_TOKEN`）が要り、測定のためだけに外部サービスへ登録するのは
> 割に合わないと判断したためである。つまり**このページの結論は変わらないが、
> 根拠は「Mac に入らない」から「アカウントが要る」に入れ替わっている**。
> 経緯は `docs/2026-09-01-embed-env-rebuild.md`。
> **このページの数字はすべて tabpfn 2.2.1 / Mac 実測**である。

### GPU はあるが使えない（正確には、使っても速くならない）

このマシンには **Radeon Pro 560X（VRAM 4GB）** が載っており、torch からも MPS 経由で見える。
しかし実測すると **CPU より速くならない**。

| 処理 | CPU | MPS（GPU） |
|---|---:|---:|
| 短文（車種名20文字）256件の埋め込み | **4.1 ms/件** | 24.6 ms/件（6倍遅い） |
| 長文（説明文2,710文字）128件の埋め込み | 174 ms/件 | **161 ms/件**（ほぼ同じ） |

2018年のノート向け GPU に対し CPU が6コア＋AVX2 を持つため実力が拮抗し、
GPU への転送コストが利得を食い潰す。短文で6倍も遅くなるのはそのため。
**このマシンが不利なのは「GPU が無いから」ではなく「Intel Mac だから」。**

なお TabPFN は **CPU で1,000行を超える学習を既定で拒否する**（遅すぎるため）。
`TABPFN_ALLOW_CPU_LARGE_DATASET=1` で解除した。`ignore_pretraining_limits=True` を
使わなかったのは、行数・特徴量数が事前学習の想定内かの検査は残したいため。

### テレメトリ

tabpfn は `posthog`（利用状況を外部送信するライブラリ）を同梱している。
`TABPFN_DISABLE_TELEMETRY=1` で止まる。`scripts/run_tabpfn.py` は既定でこれを設定する。

### 所要時間は訓練行数だけで決まる（予測行数はほぼ効かない）

事前のプローブでは予測200行で測り、本番1,102行へ**比例で引き延ばして**見積もった結果、
5-fold で70分と予想したが、実際は17分だった。

**TabPFN のコストは訓練データを Transformer に通す工程が支配的で、
予測対象の行数はほとんど効かない。** 見積もるときは訓練行数だけを見ればよい。

## 7. 再現手順

```bash
# 導入（.venv-embed の固定を壊さないよう制約付きで入れる）
.venv-embed/bin/pip install "tabpfn==2.2.1" -c requirements-embed.txt

# 所要時間の下見（訓練行数を変えて測る）
TABPFN_DISABLE_TELEMETRY=1 .venv-embed/bin/python -u scripts/run_tabpfn.py --probe

# 本番（結果は results/leaderboard.csv に追記される）
TABPFN_DISABLE_TELEMETRY=1 .venv-embed/bin/python -u scripts/run_tabpfn.py --n-estimators 8
```

`-u`（バッファなし）を付けないと、ログをファイルに落としたとき進捗が見えない。
