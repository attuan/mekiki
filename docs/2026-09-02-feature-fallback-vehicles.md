# 機能A の LLM フォールバックを Craigslist で測る — 正解の取り方を替えて成立した

**日付**: 2026-09-02
**実装**: `scripts/run_feature_fallback.py --dataset {sienta,vehicles,vehicles-type}`
**再現**: `.venv/bin/python scripts/run_feature_fallback.py --dataset vehicles-type --label-source both --encoder both`
**結果**: `results/feature_fallback_vehicles.csv`
**関連**: `docs/2026-09-01-feature-fallback.md`（シエンタでの成功）/ PRD §6.1（機能A）/ §6.3（信頼度ルーティング）

---

## 結論

- **1度目は測定として成立しなかった。** 正解を `normalize_model(model)`（入力の先頭2語）に
  取ったため正解が入力の部分文字列になり、LLM を呼ばない 0% の時点で
  宣言値内 accuracy が 1.000 に達した。ドライランで気づき、課金は $0。
- **正解を `type`（ボディ形状・13水準）に替えたら成立した。** 確信度の低い行を
  LLM に回すと accuracy はどの条件でも上がり、**人手ラベル200件＋文字TF-IDF で
  15% 回すと 0.537 → 0.620**（上限 0.822 / 下限 0.278）。回した行の accuracy は 0.817。
- **LLM の誤りの半分は pickup↔truck の入れ替わり**で、これは出品者のラベルが
  揺れているぶん（＝測定の上限）に当たる。LLM はほぼ天井まで当てている。
- 費用は 800リクエスト（うちキャッシュ命中 413）で **$1.94**。1行 $0.0016〜$0.0050。

シエンタ（`docs/2026-09-01-feature-fallback.md`）で見えた「確信度の低い行こそ LLM が
直せる行である」は、**性質の違う英語・複数車種のデータでも成り立った**。
これは信頼度ルーティング（PRD §6.3）の前提そのものである。

## 1度目 — なぜ成立しなかったか（記録）

9/1 にシエンタで出た結果（確信度の低い15%だけ LLM に回すと 0.873 → 0.942、
回した行は全問正解）が Craigslist の `model` でも成り立つかを確かめようとした。
シエンタ側の課題の作りをそのまま移した。

| | シエンタ（成功した方） | Craigslist（1度目） |
|---|---|---|
| 入力 | `タイトル` | `model`（19,739種類の自由記述） |
| 正解 | 正規表現で抜いたグレード名（116水準） | `normalize_model()` の結果＝先頭2語（5,142水準） |
| 宣言値 | カタログを見て書ける10グレード | よく出る値の上位60個 |

```
宣言した60値がカバーするのは test の 37.0%

 エスカレーション率  実際に回した行  accuracy  宣言値に限った accuracy
      0.00              0           0.370          1.000
      0.30              0           0.370          1.000
```

**LLM を1回も呼ばない 0% の時点で、宣言値に限った accuracy が 1.000。**
`normalize_model()` は「区切り記号以降を捨てて先頭2語」という規則なので、
正解が入力の部分文字列そのものになる。機能A がやっているのは文字 n-gram で
`f-150 xlt supercrew` と `f-150` を突き合わせる作業で、近傍分類にとって自明だった。
迷う行が無いので「迷った行を LLM に回す」仕組みが働く余地が無い。

残りの 63% は宣言値の外にある 5,142 水準の裾で、フォールバックのプロンプトは
「候補のいずれか1つと完全に一致する文字列を返す」と指示しているので、
**accuracy の上限はカバー率 37.0% であり、それは 0% ですでに達成されていた。**

この課題は `--dataset vehicles` として残してある（結果は
`results/feature_fallback_vehicles_rulecol.csv`）。**新しく測るときは使わないこと。**

## やり直しの設計

正解を**テキストから機械的に決まらない列**に替えた。`type` はデータ自身が持つ
出品者入力のボディ形状で、`f-150 xlt supercrew` → `pickup` には世界知識が要る。

| | 1度目 | やり直し |
|---|---|---|
| 入力 | `model` | `model`（同じ） |
| 正解 | `normalize_model(model)`＝入力由来 | `type` 列（データが持つラベル） |
| 水準 | 5,142 | 13（元データの綴りのまま。`SUV` / `mini-van` など） |
| カバー率 | 37.0% | **100.0%** |

行の選び方は既存の Craigslist 測定と揃えた。60,000行抽出（seed 42）→ `type` のある
45,430行（75.7%）→ `KFold(5, shuffle, seed42)` の fold1 → 訓練 36,344行・
採点は test から400行（費用を抑えるため）。

測る条件は2×2。教師ラベルの起点（PRD 機能A の 01）とエンコーダを掛け合わせた。

    案b 値の名前だけ … values の13語そのものを参照事例にする（ゼロショット）
    案a 人手ラベル200件 … 訓練行のうち200件だけラベルを与える（仕様書が前提にしている件数）
    文字TF-IDF … 機能A の既定エンコーダ（追加依存なし）
    e5-small   … 計算済みの多言語 e5 埋め込み（scripts/embed_vehicles.py）

案b × e5-small のためだけに、宣言値13語ぶんの埋め込みが要る（`PrecomputedEncoder` は
未知の文字列を扱えないため）。`scripts/embed_type_values.py` が model 側と同じ
モデル・同じ接頭辞で作る。

### 測る前のゲート（1度目の反省を手続きにした）

`--dry-run`（$0）で次の3つを見て、通らない課題には課金しない。
これを `run_feature_fallback.py` に組み込んである。

1. **宣言値のカバー率** — 1度目はここが 37.0% で、それがそのまま上限だった → 今回 100.0%
2. **0% の accuracy と、この課題の上限・下限** — 余地が無いなら測る意味がない
3. **確信度の下位の accuracy が、残りより実際に低いか** — 同じなら確信度は
   「LLM に回すべき行」を選べておらず、回しても直らない

**上限は「同じ入力テキストの多数決」で出す。** `type` は出品者が各出品で選ぶので
`f-150` が truck 471件 / pickup 450件 のように割れており、**入力テキストだけを見る
どんな手法もこの値を超えられない**。母集団45,430行で多数決を取り、採点する400行に
当てて **0.822**（母集団全体では 0.827）。下限は最頻クラス `sedan` を常に答える **0.278**。

なお多数決を採点400行の中だけで取ると 0.925 と過大に出る（同じ文字列がほとんど
重複しないため）。`ceiling()` は母集団で取った多数決を採点行に当てる形にしてある。

### ゲートの結果 — 通過

| 条件 | 0% の accuracy | 確信度 下位30% | 残り70% | 差 |
|---|---|---|---|---|
| 案a 人手200件 × 文字TF-IDF | 0.537 | 0.367 | 0.611 | **+0.244** |
| 案b 値の名前だけ × e5-small | 0.233 | 0.142 | 0.271 | +0.130 |
| 案a 人手200件 × e5-small | 0.530 | 0.458 | 0.561 | +0.102 |
| 案b 値の名前だけ × 文字TF-IDF | 0.142 | 0.125 | 0.150 | +0.025 |

どの条件も 0% で頭打ちになっていない（1度目との決定的な違い）。
ただし**案b × 文字TF-IDF だけは条件3を実質的に満たしていない**。
accuracy が下限 0.278 すら下回り、確信度にほとんど信号が無い。
`f-150 xlt` と `pickup` に文字の重なりが無いためで、予想どおりの結果である。
対照として測ることにした（この条件だけ外すと「効かない起点」の記録が残らない）。

共通の system プロンプトが Claude 側のキャッシュに載るため。シエンタ（$0.0028〜0.0053）と同水準。

### LLM の誤りの中身 — 半分は正解側の揺れ

最良条件（案a × 文字TF-IDF）の 30% について、回した120行の内訳を見た。
36行が正解と一致せず、**そのうち18行（50%）が pickup↔truck の入れ替わり**である。

```
正解          LLM の答え     件数
truck        pickup         10
pickup       truck           8
convertible  coupe           4
wagon        SUV             2
van          mini-van        2
```

`f150` → LLM は `pickup`・正解は `truck`、`silverado 1500` → 同じく入れ替わり、といった
具合で、**これは上限 0.822 として先に見込んでいたラベルの揺れそのもの**。
これを除けば回した行の accuracy は 0.700 → 0.850 に相当する。
残りも `convertible` と `coupe`、`van` と `mini-van` のように人でも割れる対で、
**LLM はこの課題のほぼ天井まで当てている**と読める。

## 読み方

- **信頼度ルーティングの前提は Craigslist でも成り立つ。** 確信度の低い行は
  実際に当たっておらず（下位30% が 0.367 に対し残り 0.611）、そこを LLM に回すと
  0.817 まで戻る。全行を投げる必要はない。
- **効いたのは「人手ラベル200件 × 文字TF-IDF」。** 400行のうち60行（15%）を回して
  +0.083、費用 $0.19。30% まで上げても +0.100 で頭打ちになる。
  **確信度の下から15%に、直せる行がほぼ収まっている**ということ。
- **e5-small は 0% では文字TF-IDF とほぼ同じ（0.530 / 0.537）だが、LLM を足すと負ける。**
  確信度の下位に「本当に難しい行」より「埋め込みが近すぎて割れた行」が集まり、
  LLM に回す行の選別が鈍っているためと考えられる（下位30%との差が +0.102 と小さい）。
  **埋め込みが良いほどルーティングが良くなるとは限らない。**
- **値の名前だけ（案b）はこの課題では起点にならない。** 0% で 0.142〜0.233 と
  下限（0.278）を下回る。シエンタでは案b が人手ラベルに勝ったが、それは
  グレード名がタイトルに文字どおり書かれていたためで、`model` → ボディ形状のように
  **入力と値の名前が語彙を共有しない課題では成立しない**。ただし LLM を回せば
  30% で 0.398 まで上がる（LLM は起点の悪さを部分的に埋められる）。
- **シエンタとの差。** シエンタでは回した行が 1.000 だったが、ここは 0.642〜0.817。
  課題が「テキストに書いてあるものを読み取る」から「テキストに書かれていない属性を
  世界知識で補う」に変わったぶんと、正解ラベル自体が揺れているぶんの両方が効いている。

## 測っていないこと

- **下流の MAE は測っていない**（9/1 のシエンタ版・1度目と同じ）。生成した列を
  価格予測に足す効果を見るには訓練側 36,344行も同率でエスカレーションする必要があり、
  費用の桁が変わる。中間ラベルの accuracy が上がっても下流の MAE が良くなるとは
  限らない（PRD §7-3 に順位が入れ替わった例がある）ので、**ここは要確認**。
- **fold1 のみ・400行**での測定である。
- **人手ラベルの件数は200件だけ**しか試していない。件数を増やすと 0% が上がり、
  LLM の取り分がどう変わるかは未測定。
- **能動学習の後半は未検証。** `ClaudeFallback` は答えをレビュー待ちキューに積むが、
  承認して次回の高速パスが広がるところまでは回していない。
- **欠損している `type`（24.5%）は対象外。** 値のある行だけで採点している。
