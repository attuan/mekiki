# 自由記述に正解が書いてあった — 見つけ方と塞ぎ方

**日付**: 2026-09-01
**実装**: `unfold/predictor.py` の `mask_amounts()` / `ColumnSpec.long_text`
**再現**: `.venv/bin/python scripts/run_llm_predictor.py --dataset vehicles --n-eval 120 --description 2000`
**関連**: `docs/2026-09-01-llm-predictor-vehicles.md` / CLAUDE.md「既知のデータ品質問題」

---

## 一言でいうと

Craigslist の `説明文`（出品者が書いた自由記述）を LLM に渡したら
MAE が 2,335 → 1,546 と **40% も改善した。だがこれは予測ではなく、
出品テキストに書いてある売り値を読んでいただけだった。**

**採点した 600 行のうち 262 行（43.7%）で、説明文に価格と完全一致する数字が
書かれていた。**

---

## どうやって気づいたか

改善幅が大きすぎた。fold ごとの値を見ると:

| fold | 説明文なし | 説明文あり |
|---|---|---|
| 3 | 3,360 | 1,964 |
| 4 | 2,004 | **1,308** |

MAE 1,308 USD は、価格中央値 13,950 USD に対して **9.4% の誤差**である。
中古車価格の予測でこの精度は、実務の査定士より良い。
**良すぎる結果が出たら、まずリークを疑う**のが鉄則である。

---

## 動かぬ証拠

「説明文に価格そのものが書いてある行」と「書いていない行」に分けて採点した。

| 構成 | 全600行 | 価格が書いてある行（262） | 書いていない行（338） |
|---|---|---|---|
| 説明文なし | 2,335.32 | 2,035.29 | 2,567.89 |
| **説明文あり・伏字なし** | **1,545.86** | **718.65** | 2,187.07 |
| 改善幅 | −34% | **−65%** | −15% |

**価格が書いてある行だけ極端に当たっている。** 実力なら両方が同じくらい
改善するはずで、片方だけ 65% 良くなるのは読み取り以外に説明がつかない。

実際の説明文はこうなっている（価格 $5,900 の行）:

> Just Lowered! 2008 Toyota Sienna LE 222,617 miles **$5,900** plus DMV Fees …

出品ページの本文なので、売り値が書いてあるのは当然である。
**このデータで「説明文」を特徴量にすること自体が、本質的にリークを含む。**

---

## 塞ぎ方 — 製品側の責務にした

これは中古車に限らない。**出品・求人・不動産など、自由記述に価格や条件が
書かれるデータでは常に起きる。** 「利用者が気をつける」では必ず事故るので、
`unfold` 側で既定で塞ぐことにした。

```python
from unfold.predictor import mask_amounts

mask_amounts("Just Lowered! 2008 Toyota Sienna LE 222,617 miles $5,900 plus DMV Fees")
# → 'Just Lowered! 〈数値〉 Toyota Sienna LE 〈数値〉 miles 〈金額〉 plus DMV Fees'
```

伏せる対象:

1. **金額表記** — `$12,345` / `12345 dollars` / `USD 12,345` / `123万円`
2. **単独で現れる 300〜300,000 の整数** — 価格になりうる桁をまとめて伏せる

`ColumnSpec.mask_amounts_in_long_text` が既定 `True`。
プロンプト側にも「〈金額〉〈数値〉は答えの漏れを防ぐために伏せた数字なので、
推測して埋めようとしないでください」と書いてある。

### 何を失うか（意図的な割り切り）

| 巻き込むもの | 損失 |
|---|---|
| 走行距離（222,617 miles） | **なし。** 構造化列として別に渡している |
| 年式（2008） | **なし。** 車齢として別に渡している |
| 在庫番号・電話番号 | なし。もともと価格と無関係 |
| 排気量（5.7L）・車種の数字（F-150、Model 3、911） | **残る。** 300 未満なので伏せない |

**完全ではない。** 「twelve thousand」のような綴りの金額は抜ける。
だから伏字だけに頼らず、**測定のたびにリークの有無を確認する手順**を残した
（この文書の「動かぬ証拠」の表がその手順そのもの）。

---

## 事前スクリーニングは何を言っていたか

同じ日に作った `unfold.screen()`（LLM を呼ばずにテキストの寄与を測る道具）は、
説明文について **寄与率 3.7% =「効きにくい」** と判定していた。
車種名の 15.4% と比べてずっと低い。

**この判定は正しかった。** 文字 TF-IDF は説明文から価格を取り出せないので、
「TF-IDF で使える情報は少ない」という判定になる。一方 LLM は
`$5,900` という文字列を**数値として読める**ので、TF-IDF にはできないことをした。

つまり:

> **スクリーニングと LLM の実測が大きく食い違ったら、それはリークの兆候。**

これは偶然の副産物だが、実用的な検査になる。スクリーニングが「効きにくい」と
言っている列で LLM が大きく勝ったら、**まず正解が漏れていないかを疑うこと。**

## 伏字ありで測り直した結果 — 効果は本物だった

| 構成 | 全600行 | 価格記載あり（262行） | 記載なし（338行） |
|---|---|---|---|
| 説明文なし | 2,335.32 | 2,035 | 2,568 |
| ~~説明文あり・伏字なし~~ | ~~1,545.86~~ | ~~719（**−65%**）~~ | ~~2,187（−15%）~~ |
| **説明文あり・伏字あり** | **1,980.68** | 1,739（**−14.5%**） | 2,168（**−15.6%**） |

**伏字なし版は「価格が書いてある行」だけが 65% 改善した。** 片方だけ極端に良くなるのが
読み取りの兆候である。**伏字あり版は両方が同じだけ改善した**（14.5% と 15.6%）。
一様に改善するのが本物の効果の兆候で、**伏字は正しく効いた**と判断できる。

そのうえで、説明文を渡す価値は残った。

- 説明文あり − 説明文なし: **−354.6 USD**、95%区間 [−510.3, −229.1]、良い確率 **100.0%**
- 既知の最良構成（2,591.58）に対して **23.6% の改善**、対応t検定 p = 0.016、5/5 fold で勝ち

**リークを潰しても、自由記述そのものには本物の情報が入っていた**ということである。
詳細は `docs/2026-09-01-llm-predictor-vehicles.md` の「自由記述を足したら」節。

## 教訓

1. **良すぎる結果はまずリークを疑う。** 改善幅が桁違いなら、精度が上がったのではなく
   問題が簡単になっている。
2. **自由記述には目的変数が書いてあると思って設計する。** 出品データでは
   むしろそれが普通で、例外ではない。
3. **リーク検査は「部分集合に分けて採点する」のがいちばん速い。**
   目的変数が漏れていそうな行とそうでない行に分け、片方だけ極端に当たっていないかを見る。
4. **対策はライブラリ側に置く。** CLAUDE.md にはすでに重複出稿による水増し
   （R² が 0.880 → 0.914）が記録されているが、これも同じ種類の事故である。
   **`unfold` は非構造テキストを特徴量にする道具なので、この事故が起きやすい。**
